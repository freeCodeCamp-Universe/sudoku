# Lesson authoring reference

Rules and conventions for writing lesson files. For how lessons are loaded, built, and rendered, see [`architecture.md`](architecture.md#learn-layer).

## Lesson file structure

Each lesson is `src/curriculum/lessons/<NNN>.md`. The number is a grouping convenience: module 1 uses `101.md` to `199.md`, module 2 uses `201.md` to `299.md`. `src/curriculum/ordering.ts` decides the real order. The loader ignores any file not listed there.

```ts
export const curriculum: readonly OrderingModule[] = [
  {
    module: 1,
    slug: 'getting-started',
    title: 'Getting Started',
    lessons: ['101.md', '102.md', '103.md', '104.md'],
  },
];
```

A lesson entry is a filename, or `{ file: '105.md', wip: true }` to hide one lesson. Set `wip: true` on a module to hide the whole module. Hidden lessons appear only in development with `SHOW_UPCOMING_LESSONS=true`.

**Scaffolding**

```bash
pnpm add-module --number=2 --slug=techniques --title="Techniques"
pnpm add-lesson --module=2 --title="Candidate notes"
pnpm add-lesson --module=2 --title="Candidate notes" --type=practice --after=201.md
```

`add-module` creates an intro and a review lesson. It places the module with `--before=<module>` or `--after=<module>`, or appends it. `add-lesson` takes the next free number in the module's range and inserts it before the module's review lesson, or where `--before=<file>` or `--after=<file>` says. `add-lesson` marks the new entry `wip: true`. Both scripts prompt for their values when run with no arguments.

**Frontmatter**

| Field        | Notes                                                                                                                |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| `id`         | Required. 24 hex characters, unique across the curriculum. Generated by the scaffolding scripts; never hand-edited.  |
| `title`      | Required. Rendered as the page's `<h1>` and in the curriculum tree. Renders inline markdown such as backticks.       |
| `type`       | `intro`, `learn`, `practice`, or `review`. Defaults to `learn`. Changes grouping and wording only, never validation. |
| `layoutType` | `article` or `interactive`. The loader decides the real layout from the sections present. See Layout below.          |

**Section markers**

| Marker               | Purpose                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `# --instructions--` | Markdown shown to the learner.                                                             |
| `# --files--`        | Seed files for the interactive panel: one `## <filename>` heading and code fence per file. |
| `# --config--`       | A `json` code block. See [Config block](#config-block).                                    |
| `# --author-notes--` | Notes for authors and reviewers. Never rendered.                                           |

Any other `# --name--` marker fails the build.

**Layout**

A lesson is **interactive** when it has a `# --config--` section, or when it declares `layoutType: interactive` and has a `# --files--` section. An interactive lesson shows the instructions and checklist beside the interactive panel. Every other lesson is an **article**, a centered prose column with an outline built from its H2 and H3 headings.

## Instructions

Instructions are GitHub-flavored markdown. `renderMarkdown` in `src/learn/Markdown/renderMarkdown.ts` turns them into HTML at build time.

- Do not write an H1. The title is the page's only H1. Start sections at `##`.
- H2 and H3 headings get slug IDs, so `## Seeing a cell's houses` becomes `id="seeing-a-cells-houses"`. The article outline links to them.
- Links open in a new tab with `rel="nofollow noopener noreferrer"`.
- The renderer wraps tables so they scroll horizontally on narrow screens.

### Showing the copy button on a code fence

Code fences have no copy button by default. Add `copy` to the info string to show one:

````markdown
```ts copy
const peers = 20;
```
````

`copy` works without a language too: ` ``` copy `. `no-copy` is accepted and does nothing.

### Tab groups

Article lessons can embed tabbed code viewers with `:::tabs` / `:::` regions. Interactive lessons do not render them.

````markdown
:::tabs

### row.txt

```txt
5 3 . . 7 . . . .
```

### column.txt

```txt
5
6
.
```

:::
````

- Each heading names a tab. Any level from `#` to `######` works, because the parser reads it as a tab label, not a document heading.
- Each heading must be followed by a code fence. The language tag is optional.
- A group needs at least one tab and must be closed with `:::` on its own line.

The loader parses these regions in `src/curriculum/tabBlocks.ts`. The `TabGroup` component in `src/learn/TabGroup/TabGroup.tsx` renders them with arrow-key, Home, and End navigation.

### Raw HTML

Instructions accept raw HTML from the [`sanitize-html` default allowlist](https://github.com/apostrophecms/sanitize-html#default-options), which covers tags like `kbd`, `figure`, `figcaption`, and `table`, plus `<img>`. Anything else fails the build, including `<canvas>`, event handler attributes, and `javascript:` URLs. The check skips inline code and code fences, so you can show HTML as an example.

| Tag     | Allowed attributes                                            |
| ------- | ------------------------------------------------------------- |
| `<img>` | `src`, `srcset`, `alt`, `title`, `width`, `height`, `loading` |

The allowlist is `LESSON_HTML_OPTIONS` in `src/curriculum/sanitize.ts`.

## Images

Every `<img>` needs an `alt` attribute, or the build fails. Describe what the image shows. Use `alt=""` when the image is decorative or its meaning is already in the text.

```html
<img
  src="/images/learn/houses.svg"
  alt="Three 9 by 9 grids side by side. The first shades the fifth row, the second shades the fifth column, and the third shades the center 3 by 3 box."
  width="404"
  height="168"
/>
```

- Put local images in `public/images/learn/` and reference them from the site root, as `/images/learn/<file>`.
- Remote images must use `https`. They add a third-party request for every learner and can change or disappear, so prefer local files for anything the lesson depends on.
- Set `width` and `height` so the page does not shift while the image loads. The image shrinks to fit narrow columns and keeps its aspect ratio.
- Markdown syntax like `![alt text](/images/learn/houses.svg)` also works and always produces an `alt`, but it cannot set `width` or `height`.
- Text inside an image is invisible to screen readers. Put anything the learner must read into the `alt` or the prose.

## Config block

The `# --config--` section holds one code fence labeled `json`. Any other label, including `jsonc`, fails the build. `parseJsonWithComments` in `src/curriculum/jsonWithComments.ts` strips `//` and `/* */` comments, then parses the rest as strict JSON, so trailing commas still fail.

````markdown
# --config--

```json
{
  // Each checklist item appears under the instructions.
  "checklist": [
    {
      "label": "See the three kinds of house",
      "hint": "You can find a row, a column, and a box shaded in the diagram.",
      /* Engine-specific. The placeholder panel never evaluates it. */
      "test": { "placeholder": true }
    }
  ]
}
```
````

| Property    | Notes                                                                                |
| ----------- | ------------------------------------------------------------------------------------ |
| `checklist` | Array of checklist items. See [Checklist items](#checklist-items). Defaults to `[]`. |

## Checklist items

Structure: `{ "label": "...", "hint": "...", "test": { ... } }`. `hint` is optional.

- **`label`** appears in the checklist. Name the action the learner completes.
- **`hint`** appears under an unfinished item when the learner tries to go to the next lesson before finishing it. It must start with `You can` or `You should`, or `curriculumIntegrity.test.ts` fails.
- **`test`** is an engine-specific object the curriculum layer never reads. The interactive panel's `LessonEngine`, defined in `src/curriculum/lessonEngine.ts`, evaluates it. The current `PlaceholderPanel` marks every item complete, so `{ "placeholder": true }` is the only test in use.

## Files block

`# --files--` seeds the interactive panel. Each `## <filename>` heading is followed by one code fence holding that file's contents:

````markdown
# --files--

## starter.txt

```txt
Replace this with the lesson's seed state.
```
````

## Author notes

`# --author-notes--` is free-form markdown for authors and reviewers. Record the lesson's goal and the decisions behind it. Learners never see it.

## Previewing and verifying

Copy `sample.env` to `.env` and set `SHOW_LEARN=true`. Set `SHOW_UPCOMING_LESSONS=true` too if you want to see WIP lessons. Then run `pnpm dev` and open `/learn`. The dev server rebuilds lesson data when a lesson file changes.

Before finishing, run:

```bash
pnpm build && pnpm test && pnpm lint
```

Lesson parsing errors fail both the build and `curriculumIntegrity.test.ts`. That covers unknown sections, a missing `alt`, disallowed HTML, and invalid config. `pnpm lint` runs Prettier over lesson files.
